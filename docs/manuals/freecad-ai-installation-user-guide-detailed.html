1. Scope and release status

This guide applies to FreeCAD AI 0.23.1-alpha. It is alpha software: save documents before AI-assisted changes, keep recoverable copies of important models, and expect interfaces or configuration fields to change.

Security status. Deterministic unit and security tests are green, but the complete supported FreeCAD/Python/PySide/Qt host matrix has not been verified. Live GUI, live MCP, private-LAN, actual-host vulnerability scanning, and Windows ACL equivalence remain explicit release HOLDs. See Limitations and HOLDs before production use.

FreeCAD AI can modify the active FreeCAD document. Structured tools reduce the attack surface, but neither tool calling nor code preflight is an operating-system sandbox. Treat model output, project instructions, user tools, hooks, macros, and LLM responses as untrusted until reviewed.

2. Prerequisites

  • FreeCAD 1.0 or newer. FreeCAD 1.1+ commonly uses version-scoped user directories.
  • Python 3.11 or newer in the FreeCAD runtime. The system Python is not necessarily the Python embedded in FreeCAD.
  • An LLM provider: a local service such as Ollama, or a cloud provider account and API key.
  • Git for a clone-based installation, or an archive tool for a manual copy.
  • Permission to write to the current user's FreeCAD Mod directory.

FreeCAD AI declares no PyPI runtime dependencies and uses the Python standard library. FreeCAD, PySide, and Qt are supplied by the host and must be assessed as part of the actual runtime.

Check the host runtime

In FreeCAD, open View → Panels → Python console and inspect the actual runtime:

import sys, FreeCAD
print("FreeCAD:", FreeCAD.Version())
print("Python:", sys.version)
print("User config:", FreeCAD.getUserConfigDir())

If Python is older than 3.11, install a supported FreeCAD build rather than trying to replace packages inside FreeCAD's bundled runtime.

3. Install by platform

The directory placed below Mod must contain Init.py, InitGui.py, package.xml, and the freecad_ai package. Do not add an extra archive-name directory around them.

Linux

git clone https://github.com/ghbalf/freecad-ai.git "$HOME/src/freecad-ai"
mkdir -p "$HOME/.local/share/FreeCAD/Mod"
ln -s "$HOME/src/freecad-ai" "$HOME/.local/share/FreeCAD/Mod/freecad-ai"

For FreeCAD 1.1, the canonical module directory is commonly ~/.local/share/FreeCAD/v1.1/Mod/. Substitute the version used by your installation:

mkdir -p "$HOME/.local/share/FreeCAD/v1.1/Mod"
ln -s "$HOME/src/freecad-ai" "$HOME/.local/share/FreeCAD/v1.1/Mod/freecad-ai"

Flatpak and distribution-packaged builds may use a sandbox-specific data root. Confirm the user application-data directory from the running FreeCAD build instead of guessing.

macOS

git clone https://github.com/ghbalf/freecad-ai.git "$HOME/src/freecad-ai"
mkdir -p "$HOME/Library/Application Support/FreeCAD/Mod"
ln -s "$HOME/src/freecad-ai" \
  "$HOME/Library/Application Support/FreeCAD/Mod/freecad-ai"

FreeCAD 1.1+ may place Mod below a version folder such as v1.1. Use the version-scoped path reported by your FreeCAD build if the unversioned location is not discovered.

Windows

The simplest method is to copy the repository folder to the current user's FreeCAD Mod directory:

git clone https://github.com/ghbalf/freecad-ai.git "$env:USERPROFILE\src\freecad-ai"
New-Item -ItemType Directory -Force "$env:APPDATA\FreeCAD\Mod" | Out-Null
Copy-Item -Recurse "$env:USERPROFILE\src\freecad-ai" \
  "$env:APPDATA\FreeCAD\Mod\freecad-ai"

Alternatively, from an elevated PowerShell prompt, create a directory symbolic link:

New-Item -ItemType SymbolicLink \
  -Path "$env:APPDATA\FreeCAD\Mod\freecad-ai" \
  -Target "$env:USERPROFILE\src\freecad-ai"

For FreeCAD 1.1+, insert the current version folder, for example %APPDATA%\FreeCAD\v1.1\Mod\, if that is the application-data layout selected by the installed build.

Activate the workbench

  1. Save open documents and close FreeCAD normally.
  2. Start FreeCAD again.
  3. Select FreeCAD AI from the workbench selector.
  4. If it is missing, use Workbench does not appear.

4. Configuration paths and files

The notation <FreeCADAI dir> in this guide means the resolved private configuration directory. Resolution order is:

  1. FREECAD_AI_CONFIG_DIR, when explicitly set.
  2. <FreeCAD user config directory>/FreeCADAI/ while running in FreeCAD.
  3. ~/.config/FreeCAD/FreeCADAI/ only when FreeCAD cannot be imported, such as a plain Python process.

The authoritative way to find the active directory is the FreeCAD Python console:

import os, FreeCAD
print(os.path.join(FreeCAD.getUserConfigDir(), "FreeCADAI"))
Important entries below <FreeCADAI dir>
PathPurposeSecurity note
config.jsonMain workbench configurationWritten atomically; may contain provider references and preferences.
secrets/Migrated literal provider secretsManaged as private files on POSIX.
mcp_server.tokenManaged HTTP MCP Bearer tokenNever paste its value into documentation, tickets, or logs.
conversations/Saved chat sessionsContains full conversation content.
logs/Session logsMetadata-only by default; full logging is sensitive.
skills/, tools/, hooks/User extensionsReview as executable or prompt-affecting content.
backups/Pre-execution document recovery snapshotsMay contain sensitive model data.

On POSIX systems, managed directories and files are hardened to owner-only modes where supported. Windows permission behavior is not claimed to be equivalent to POSIX ACL enforcement.

Using an isolated profile

# Linux/macOS example — set before launching FreeCAD
FREECAD_AI_CONFIG_DIR="$HOME/freecad-ai-profiles/test" freecad
# Windows PowerShell example
$env:FREECAD_AI_CONFIG_DIR = "$env:USERPROFILE\freecad-ai-profiles\test"
& "C:\Program Files\FreeCAD 1.1\bin\FreeCAD.exe"

Do not point a production profile at a repository checkout. Synced folders can replicate secrets and conversations; assess the sync provider and endpoint encryption before using one.

5. Providers, models, and secret handling

Open the chat panel's gear menu or Edit → Preferences → FreeCAD AI. Choose the provider, base URL, model, token limit, and model parameters. The workbench includes presets for Anthropic, OpenAI, Ollama, Gemini, OpenRouter, Moonshot, DeepSeek, Qwen, Groq, Mistral, Together, Fireworks, xAI, Cohere, SambaNova, MiniMax, Llama, GitHub Models, Hugging Face, Zhipu, and custom OpenAI-compatible endpoints.

Recommended secret choices

  1. Local provider: Ollama normally needs no API key.
  2. file: reference: store a secret in a separate owner-readable file and enter a value such as file:~/.config/provider-key.
  3. cmd: reference: retrieve a secret from an OS credential-store command. This explicitly executes a user-managed shell command; review it carefully.
  4. Literal value: supported for compatibility. On load, known literal provider and reranker secrets are migrated losslessly to managed private files after verified write/read-back.
Do not put secrets in project files. Keep API keys out of AGENTS.md, prompts, source control, screenshots, support bundles, and MCP client logs. A file: or cmd: reference is intentionally retained as a reference; logging redaction does not execute commands or read arbitrary referenced files to discover more values.

TLS behavior

Cloud HTTPS requests require a verified SSL context. If certificate verification cannot be initialized, the request fails before network access; there is no unverified TLS fallback. Correct the host certificate store, proxy trust, date/time, or provider URL rather than disabling verification.

6. First-run checklist

  1. Open or create a disposable FreeCAD document.
  2. Select the FreeCAD AI workbench and open its chat dock.
  3. Open Settings, select a provider and model, then configure a secret reference if needed.
  4. Start in Plan mode and keep automatic execution disabled.
  5. Send a low-risk request, such as “Describe the active document without changing it.”
  6. For a modeling smoke test, request a simple box in the disposable document and inspect the proposed action before approval.
  7. Save the result under a new filename only after verifying geometry and document state.

If the workbench discovers project instructions, resolve the preview dialog before the provider request. If you did not expect project instructions, choose Cancel and inspect the files first.

7. Plan mode, Act mode, and structured tools

Plan mode

Plan mode is suited to exploration and review. The assistant can propose Python, which is displayed in a review dialog. Use Check for a compatibility preflight, inspect the code, and execute only when the intended document and effects are clear. Fix with AI sends the code and your correction request back to the provider.

Act mode

Act mode prefers typed, bounded tools. Typical operations create primitives, sketches, pads, pockets, booleans, patterns, transforms, measurements, exports, and document queries. Structured tools are still capable of modifying the active document, but their schemas constrain arguments and make intent easier to review than arbitrary Python.

A safe operating pattern

  1. Ask the assistant to inspect the document with read-oriented tools.
  2. Request a short plan naming objects and dimensions.
  3. Use structured tools for the change.
  4. Inspect the tree, geometry, units, and active document after each significant step.
  5. Use FreeCAD undo or a saved copy if the result is wrong.

Tool reranking can reduce the tool schemas sent per turn. Pinned tools are intersected with the tools currently allowed by the active capability policy; reranking cannot re-enable AI Python.

Dangerous Mode is separate. It relaxes execution safeguards and can allow arbitrary paths, shell activity, or unbounded execution. It is not required to enable AI Python, and enabling one does not enable the other. Leave Dangerous Mode off unless you have a separately reviewed power-user need.

8. Opt-in AI Python and per-call review

execute_code is absent from the normal model tool schema and system guidance. To make it available in the GUI:

  1. Enable the dedicated Allow AI Python control.
  2. Read the warning and explicitly confirm; the safe default is No.
  3. Review every individual proposed code block in the code-review dialog.

The permission is process-only, is not persisted to configuration, and starts disabled in a new process. It is independent of Dangerous Mode. Each call is checked again immediately before dispatch, so stale schemas or a changed toggle cannot bypass the gate. Rejecting a code call stops the remaining tool batch and prevents a provider retry for that denied request.

Preflight statuses

StatusMeaningAllowed response
PASSEDThe compatibility preflight completed without a detected validation error.You may still review and approve or cancel. This is not proof of safety.
REJECTEDThe preflight detected a definite validation failure.Execution is blocked; there is no override.
UNAVAILABLEThe preflight environment could not be used.GUI-only second warning may allow execution without preflight.
ERRORThe preflight itself failed unexpectedly.GUI-only second warning may allow execution without preflight.
Preflight is not isolation. Approved code runs with the FreeCAD user's OS permissions and can read or modify accessible files, start processes, use the network, expose secrets, or damage a document. Prefer structured tools. Review imports, file paths, subprocess use, network calls, loops, and the active document before approval.

9. AGENTS.md and FREECAD_AI.md project instructions

Place AGENTS.md or FREECAD_AI.md beside an .FCStd document to provide project conventions such as units, naming, or preferred modeling workflows. Discovery checks the document directory, up to three parent levels, and then <FreeCADAI dir>/AGENTS.md.

# AGENTS.md
Use millimetres.
Prefer PartDesign Body → Sketch → Pad.
Ask before exporting or overwriting a file.

Trust workflow

Before any content reaches a provider, the dialog shows the canonical root, source, ordered manifest, SHA-256 fingerprint, and exact preview snapshot. Choose:

  • Trust and send: allow exactly that fingerprint.
  • Ignore this version: send no project-instruction text for that fingerprint.
  • Cancel: abort the request without clearing the input, attachments, or conversation.

A changed fingerprint triggers a new preview. The approved in-memory snapshot—not a later disk reread—is used in the request.

Include and content boundaries

Includes must be relative, contained by the canonical instruction root, regular files, non-symlinks, and strict UTF-8. Absolute paths, .. traversal, sibling-prefix tricks, symlink escapes, cycles, NUL bytes, excessive depth, and oversized bundles reject the entire bundle. Current limits are 64 KiB per file, 256 KiB total, and five include levels.

Local-race limitation. The current resolver validates a path before opening it rather than descriptor-pinning every AGENTS read. Fingerprint plus exact preview prevents unreviewed provider transmission, but descriptor-pinned open/fstat is still tracked as defense-in-depth against a concurrent local path swap.

Supported substitutions include {{document_name}}, {{object_count}}, and {{active_body}}. The fingerprint is based on the raw instruction files and manifest, so changing live document variables does not silently create a different trusted file version.

10. HTTP MCP with mandatory Bearer authentication

HTTP MCP exposes structured FreeCAD tools to an external client. It supports Streamable HTTP at /mcp and a legacy SSE endpoint for compatibility. execute_code is physically excluded from the HTTP registry; authenticated run_macro remains available.

Do not expose this server to the Internet. Binding is limited to loopback or one unambiguous private/link-local numeric address. HTTP does not encrypt the Bearer token or model traffic. A same-LAN observer may capture them. Use loopback by default.

Managed token

On first start, the managed token is exclusively generated at <FreeCADAI dir>/mcp_server.token with high entropy and private POSIX permissions. Startup reports the path, never the value. The same token is reused until deliberately rotated.

Custom token file

Set MCP_TOKEN_FILE only when a separate secret-management workflow owns the token. The file must already exist, be non-empty and correctly formatted, be a regular non-symlink file owned by the current user, and have restrictive permissions. FreeCAD AI treats a custom path as read-only: it does not create, chmod, replace, or truncate it. Any validation failure aborts before backend creation or network bind.

Start inside FreeCAD

Use the MCP Server toolbar/menu action, or start the same controller from a terminal:

# Linux AppImage example; defaults to 127.0.0.1:3000
/path/to/FreeCAD.AppImage /path/to/freecad-ai/mcp_server_http.py

Optional environment settings are MCP_HOST, MCP_PORT, MCP_ALLOWED_HOSTS, and MCP_TOKEN_FILE. A hostname is resolved exactly once and must produce one acceptable address; the server binds the resulting numeric address. Wildcard, public, unspecified, multicast, ambiguous, mapped, and unsupported scoped addresses fail closed.

Test without exposing the token in process arguments

The following loopback example streams a curl configuration through standard input. The token is not placed in curl's command-line arguments. Disable shell tracing first and do not capture standard input:

set +x
MCP_URL='http://127.0.0.1:3000/mcp'
MCP_TOKEN_FILE='/replace/with/the/reported/token/path'

# Negative check: expected HTTP 401.
curl --silent --show-error --output /dev/null --write-out '%{http_code}\n' \
  -X POST "$MCP_URL" -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'

# Authenticated check: token travels on stdin, not argv.
{ printf 'header = "Authorization: Bearer '; \
  tr -d '\r\n' < "$MCP_TOKEN_FILE"; printf '"\n'; } |
  curl --config - --silent --show-error -X POST "$MCP_URL" \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'

Inspect the response without writing the Authorization header. Confirm that execute_code is absent and that only expected structured tools are listed.

HTTP response guide

StatusLikely causeAction
401Missing, malformed, duplicate, or wrong Bearer authorizationVerify the client reads the correct token file without printing it.
403Rejected Host or Origin policyUse the numeric address actually bound and an explicit allowed host.
429Global request bucket exhaustedHonor Retry-After and reduce request rate.
503Eight concurrent request slots are occupiedClose stale SSE sessions or retry later; do not raise limits casually.

Authentication is applied to every route and verb before body parsing and dispatch. Default admission is 60 requests per minute with burst 20 and at most eight concurrent requests reserved before worker-thread creation.

11. STDIO MCP

STDIO mode lets an MCP client spawn a headless FreeCAD process and exchange JSON-RPC on standard input/output. It has no HTTP listener or Bearer token. For compatibility, its registry still includes execute_code; this is an accepted privileged boundary, not a claim of safety.

claude mcp add freecad -- bash -c \
  'exec 3>&1 1>&2 && /path/to/FreeCAD.AppImage -c /path/to/freecad-ai/mcp_server_entry.py'

The shell wrapper moves FreeCAD's startup banner to standard error and reserves clean standard output for MCP JSON-RPC. Adjust the FreeCAD executable path for the platform and client. Review client-side tool permissions, because a local STDIO client can invoke the capabilities exposed by this registry.

Choose STDIO when the client should own a separate FreeCAD process. Choose authenticated loopback HTTP when an authorized client must operate the document visible in an existing GUI process. Do not weaken HTTP authentication to mimic STDIO.

12. Conversations, logs, and privacy

  • Conversations are saved with full message content so sessions can be resumed.
  • Session logs default to metadata: tool name, success, duration, turn, and error class—without messages, arguments, or results.
  • Full logging is an explicit diagnostic opt-in. Known key names and configured literal secrets are recursively redacted, but ordinary sensitive document content may remain.
  • Provider requests may include prompts, document context, selected object data, attachments, screenshots, and approved project instructions. Review the provider's retention and training policy.
  • Default retention limits are zero, meaning automatic deletion is disabled. Configure age/count retention deliberately and back up before changing it.

Before sharing a support bundle, inspect config.json, conversations, logs, project instructions, macros, and attachments. Do not rely on redaction as the sole control for a full diagnostic log.

13. Generate an actual-runtime CycloneDX SBOM

The inventory must run inside the target FreeCAD runtime. It emits CycloneDX 1.5 JSON containing exactly five required components: FreeCAD AI, FreeCAD, Python, the active PySide binding, and Qt. Missing or unsafe version strings cause a non-zero exit and no apparently complete BOM.

# Run with the target host's FreeCAD command, not an unrelated system Python.
/path/to/FreeCADCmd -c "import sys; from freecad_ai.runtime_inventory import main; sys.exit(main(['--output','/private/output/freecad-ai-runtime.cdx.json']))"

The explicit output refuses symlinks and is written privately and atomically on POSIX. Review the JSON for unexpected identity or path fields, validate it against the CycloneDX 1.5 schema, then scan the same immutable file with an approved, current scanner such as Grype or Trivy.

Do not confuse scopes. A successful pip-audit over the explicitly empty declared PyPI dependency set does not audit host-provided FreeCAD, Python, PySide, or Qt. Release evidence requires the actual-host SBOM and an external vulnerability scan.

14. Troubleshooting

The workbench does not appear
  1. Confirm the installed folder directly contains InitGui.py.
  2. Check the version-scoped Mod directory for FreeCAD 1.1+.
  3. Open View → Panels → Report view and inspect import errors.
  4. Verify the Python runtime is 3.11 or newer.
  5. Check that a symlink target still exists and is readable.
Provider requests fail before connecting

Verify the base URL, provider/model pairing, and secret reference. For HTTPS certificate errors, repair the CA/proxy environment; no insecure TLS fallback exists. For a file: reference, check that the expanded path exists and is readable. For cmd:, run and review the command separately without logging its output.

AI Python is missing from the model's tools

This is the secure default. Enable Allow AI Python for the current process and confirm the warning. A new process starts locked. Dangerous Mode is unrelated. HTTP MCP never exposes execute_code, even when the GUI toggle is armed.

Project instructions stop the request

Inspect every path in the preview. Remove absolute/traversing includes, symlinks, invalid UTF-8, cycles, or oversized content. Resolver errors fail closed and leave the draft request intact. Do not bypass the resolver by copying unreviewed instruction text into a prompt.

HTTP MCP will not start

Check the reported error without pasting the token. Custom token files must pass owner, mode, type, non-symlink, and content checks. The host must resolve once to one allowed numeric address. Public, wildcard, ambiguous, multicast, unspecified, mapped, or unsupported scoped addresses are rejected before backend creation.

HTTP MCP starts, but the client cannot connect

Confirm the client uses /mcp, sends exactly one Bearer header on every request, and dials the bound numeric address. A 401 indicates authentication; 403 indicates Host/Origin; 429 indicates rate limiting; 503 indicates concurrency saturation. Some MCP clients discover tools only at session start and must begin a new client session after configuration.

A test suite exits successfully but reports skips

Skips are not acceptance evidence. In the remediation environment, all 88 selected integration tests skipped because the FreeCAD AppImage was absent. Keep GUI/runtime release approval on HOLD until every required test executes and passes in a supported host.

15. Upgrade and rollback

Before an upgrade

  1. Save and close important FreeCAD documents.
  2. Record the current add-on version or Git commit.
  3. Make a protected backup of <FreeCADAI dir>, including conversations, trust records, and secret references. Protect the backup like the original.
  4. Do not delete migration snapshots or old secret files until the new version has been verified.

Upgrade a clone

cd /path/to/freecad-ai
git status --short
git fetch --tags
# Select a reviewed release/tag according to your change-control policy.

Do not overwrite a dirty checkout. Preserve local changes in a recoverable branch or patch before selecting a new version. Save work and restart FreeCAD manually only when you are ready to load the new add-on code.

Rollback

  1. Stop making document changes and save a copy under a new name.
  2. Record the exact failure and version; do not include secrets.
  3. Restore the prior reviewed add-on directory or commit.
  4. Retain migrated secret and trust files. Do not weaken permissions or enable unauthenticated HTTP as a workaround.
  5. Restart FreeCAD only after saving work and confirming the intended process.
  6. Verify provider access, project-instruction preview, AI-Python default lock, and MCP authentication using a disposable document.

Configuration rollback is not automatically equivalent to source rollback: older versions may ignore new fields or lack authenticated HTTP. If an older build cannot use the secure HTTP contract, use a reviewed STDIO workflow rather than restoring an unauthenticated listener.
