1. Scope and safety model

scripts/install_macos.sh installs the checkout as the current user's FreeCAD workbench. It refuses an effective-root invocation before target mutation. Its normal write scope is one canonicalized user FreeCAD Mod directory, an installer-owned sibling lock/stage, and the freecad-ai destination or an explicit replacement backup. It does not use sudo, install packages, access a network, start FreeCAD, edit provider settings, or read API keys.

Alpha and runtime status. Automated installer tests pass, but this validation host does not have a supported FreeCAD application or CLI. Successful installation and --check prove filesystem layout, not that FreeCAD can load the workbench. Live FreeCAD acceptance remains HOLD.

The default is a symbolic link, which is convenient for a development checkout. --copy creates a self-contained workbench directory. Existing content is never silently overwritten. A conflict requires the explicit --replace option, and the old object is preserved as a sibling backup.

2. Requirements

  • macOS; the installer exits before mutation when uname -s is not Darwin.
  • Apple's system Bash 3.2 at /bin/bash.
  • Standard macOS commands, including mktemp, mv, ln, and /usr/bin/rsync.
  • A complete checkout containing Init.py, InitGui.py, package.xml, and freecad_ai/.
  • A non-root user with write permission to the selected user Mod directory.

No Python virtual environment is required to run the installer. FreeCAD AI itself requires FreeCAD 1.0+ and Python 3.11+ in the FreeCAD runtime.

3. Prepare and validate the checkout

Run the installer from a trusted, reviewed checkout. Paths containing spaces are supported. First inspect repository state and the installer help:

cd "/path/with spaces/freecad-ai"
git status --short
/bin/bash scripts/install_macos.sh --help

The source is the physical parent of the installer's scripts directory. The four required workbench entries are validated before any target directory is created. Do not detach or copy only the script: it must remain inside the checkout it installs.

Save before setup. The script never launches or restarts FreeCAD. Save open documents and close FreeCAD yourself before the first load or an upgrade so the application does not retain old Python modules.

4. How the destination is selected

The destination is always <selected Mod>/freecad-ai. Selection is deterministic:

  1. An absolute --mod-dir has highest precedence.
  2. Otherwise, if exactly one existing ~/Library/Application Support/FreeCAD/v*/Mod directory exists, it is selected.
  3. If more than one exists, the installer fails closed and asks for --mod-dir.
  4. If none exists, the generic ~/Library/Application Support/FreeCAD/Mod path is selected.

Relative paths, the filesystem root, and explicit paths containing . or .. components are rejected. The physical existing ancestor is resolved before use, so a user-looking symlink cannot disguise a system directory. Canonical paths below /System, /Library, /Applications, /usr, /private/etc, and other protected prefixes are rejected even during dry-run. To see the exact source and destination without creating anything, use --dry-run.

# Example for a FreeCAD 1.1 user directory
/bin/bash scripts/install_macos.sh --dry-run \
  --mod-dir "$HOME/Library/Application Support/FreeCAD/v1.1/Mod"

Do not choose a system-wide directory or the root of a volume. Do not run the installer with sudo; root execution is deliberately refused.

5. Preview and inspect without mutation

--dry-run validates platform, source, options, target selection, and current destination state, then reports the prospective action. It does not create the selected Mod directory, staging directory, destination, or backup.

# Preview the default link installation
/bin/bash scripts/install_macos.sh --dry-run

# Preview replacing a conflict with a standalone copy
/bin/bash scripts/install_macos.sh --copy --replace --dry-run \
  --mod-dir "/absolute/path/to/Mod"

Read the printed Source and Destination. Stop if either is unexpected. A dry run is particularly important when multiple FreeCAD releases or custom user directories exist.

6. Default symbolic-link installation

cd "/path/to/freecad-ai"
/bin/bash scripts/install_macos.sh

The installer acquires an installer-owned per-target lock, creates a private sibling staging directory, and builds and validates the proposed link there. It then claims the final destination directly with ln -s; it does not move the staged link into an attacker-created directory. Raced destinations fail closed, nested-link artifacts are removed, and a prior backup is preserved or restored according to ownership. A correct link resolving to this physical checkout is an idempotent no-op; rerunning the same command creates no backup.

When to use link mode

  • You develop or inspect the checkout in place.
  • You want repository updates to be visible after a later manual FreeCAD restart.
  • The checkout remains on a mounted and stable path.
Moving the checkout breaks the link. A broken link is treated as a conflict, not as an absent destination. Restore the source path or use an explicit reviewed replacement.

7. Standalone copy installation

cd "/path/to/freecad-ai"
/bin/bash scripts/install_macos.sh --copy

Copy mode uses the macOS system /usr/bin/rsync -a to build a staged workbench. It excludes development-only data such as .git, .github, virtual environments, tests, documentation, build/cache/coverage output, editor metadata, and egg-info. The staged copy must contain the required workbench entries. Publication then claims an absent final destination with direct mkdir and performs a final /usr/bin/rsync from the validated stage. Failure or TERM removes installer-owned partial content, releases the lock, and restores an explicit replacement backup when safe.

A structurally valid copied workbench is an idempotent no-op only when --copy is requested. Running link mode against a copy—or copy mode against a link—is a mode conflict and requires --replace.

When to use copy mode

  • You want the installed workbench independent of the checkout location.
  • You want an explicit snapshot rather than live development files.
  • You accept that repository updates do not update the installed copy automatically.

8. Conflicts, replacement, and backups

A file, directory, wrong link, broken link, or valid installation of the other mode is a conflict. Without --replace, the installer exits nonzero and leaves it unchanged.

# First preview the exact replacement
/bin/bash scripts/install_macos.sh --dry-run --replace \
  --mod-dir "/absolute/path/to/Mod"

# Then perform it only after reviewing Source and Destination
/bin/bash scripts/install_macos.sh --replace \
  --mod-dir "/absolute/path/to/Mod"

Replacement first moves the old destination to a sibling named like freecad-ai.backup.YYYYMMDD-HHMMSS.PID. If that name exists, a numeric suffix is added rather than overwriting it. After validation, publication uses a direct exclusive destination claim. A per-target lock prevents two installer transactions from intentionally sharing the same target; a stale pre-existing lock is left untouched and reported rather than removed.

If publication fails, the script attempts to move the backup back to the original destination and exits nonzero. If automatic restoration also fails, the diagnostic names the retained backup. Never delete a backup until the new workbench has been checked and loaded successfully in FreeCAD.

9. Check the installed filesystem state

/bin/bash scripts/install_macos.sh --check

# Or check a specific FreeCAD release
/bin/bash scripts/install_macos.sh --check \
  --mod-dir "$HOME/Library/Application Support/FreeCAD/v1.1/Mod"

--check is read-only. It passes for either a link resolving to the current checkout or a non-link directory containing the required workbench structure. It fails for absence, foreign content, wrong links, and broken links. It cannot be combined with --copy, --replace, or --dry-run.

Structural check only. A copied installation is checked for the required entry points, not byte-for-byte equality with the current checkout. The command does not import Python, start FreeCAD, validate provider settings, or prove GUI compatibility.

10. First run in FreeCAD

  1. Save all documents and close any existing FreeCAD process normally.
  2. Start the intended FreeCAD release yourself.
  3. Select FreeCAD AI from the workbench selector.
  4. Open the Report view and record any import error without including secrets.
  5. Confirm FreeCAD is 1.0+ and its embedded Python is 3.11+.
  6. Use a disposable document for the first modeling test.
  7. Configure a provider through the workbench settings; keep API keys out of project files and diagnostics.

The installer does not configure providers, secrets, HTTP MCP, or project trust. Consult the FreeCAD AI user/security manuals for those separate controls.

12. Recovery and rollback

  1. Save open FreeCAD work under a new filename and close the exact application process normally.
  2. Identify the printed destination and backup path. Do not use a broad wildcard.
  3. Inspect each path with ls -ld before moving anything.
  4. If the new destination must be retained for diagnosis, rename it to a unique sibling; do not overwrite the backup.
  5. Move the exact backup path back to the exact freecad-ai destination.
  6. Run --check against the explicit Mod directory.
  7. Start FreeCAD manually and verify the restored version with a disposable document.
# Illustrative only: replace both placeholders with inspected exact paths.
ls -ld "/absolute/Mod/freecad-ai" \
  "/absolute/Mod/freecad-ai.backup.YYYYMMDD-HHMMSS.PID"

# Move only after confirming the destination is absent and paths are exact.
mv "/absolute/Mod/freecad-ai.backup.YYYYMMDD-HHMMSS.PID" \
  "/absolute/Mod/freecad-ai"
Do not run the illustrative mv blindly. If both destination and backup exist, stop and decide what must be preserved. The installer never provides authority to delete user data or restart a process.

13. Current limitations and HOLDs

  • Live FreeCAD load: HOLD. No supported FreeCAD application/CLI was available on the validation host.
  • Filesystem implementation and tests: PASS. Root and independent focused runs each passed all 56 tests; the complete unit suite passed 1,612 tests. Every run had zero skips.
  • Real-host read-only checks: PASS. Darwin dry-run resolved /Users/turgay/Library/Application Support/FreeCAD/Mod/freecad-ai with the profile absent before and after. The real --check returned the expected nonzero absent result and likewise made no change.
  • Copy verification: structural, not cryptographic or version-manifest based.
  • Discovery: deliberately fails when multiple versioned Mod directories exist rather than guessing.
  • Backup lifecycle: backups are retained for user-controlled recovery; automatic pruning is not implemented.
  • Distribution: the script is not a signed/notarized macOS package and does not establish release provenance by itself.
  • Security review: PASS, 97.4%. C1 99%, C2 98%, C3 97%, C4 97%, C5 96%. The first headless agy attempt was permission-blocked; a later independent architecture review ran it correctly, incorporated real findings, and the final scoped review passed.

Use the installer only after reviewing its source and destination output. Treat a successful install as readiness for a separately controlled FreeCAD runtime acceptance, not as final release certification.
