Quick installation & first use

Install the workbench, connect an AI provider, and make a first reviewed change safely.

Alpha notice: FreeCAD AI requires FreeCAD 1.0 or newer and Python 3.11 or newer. The complete FreeCAD/Python/PySide/Qt host matrix is not yet verified; keep backups of important documents.

1. Prerequisites

  • FreeCAD 1.0+ with Python 3.11+.
  • This repository checked out or downloaded locally.
  • Either local Ollama, or an API key for a supported cloud provider.
  • Permission to place the add-on in FreeCAD's Mod directory.

2. Install the workbench

Replace /path/to/freecad-ai with this repository's absolute path. FreeCAD 1.1+ normally uses a version-scoped directory such as v1.1/Mod; substitute your installed version where shown.

Linux

mkdir -p ~/.local/share/FreeCAD/v1.1/Mod
ln -s /path/to/freecad-ai \
  ~/.local/share/FreeCAD/v1.1/Mod/freecad-ai

macOS

mkdir -p "$HOME/Library/Application Support/FreeCAD/v1.1/Mod"
ln -s /path/to/freecad-ai \
  "$HOME/Library/Application Support/FreeCAD/v1.1/Mod/freecad-ai"

Windows PowerShell

New-Item -ItemType Directory -Force `
  "$env:APPDATA\FreeCAD\v1.1\Mod"
New-Item -ItemType SymbolicLink `
  -Path "$env:APPDATA\FreeCAD\v1.1\Mod\freecad-ai" `
  -Target "C:\path\to\freecad-ai"

Use an elevated shell or Windows Developer Mode for the symlink, or copy the repository to the target path.

Close and reopen FreeCAD, then select FreeCAD AI from the workbench selector.

3. Configure a provider

  1. Open Edit → Preferences → FreeCAD AI, or use the gear button in the chat panel.
  2. Select a provider and model. For Ollama, use the local endpoint and no cloud key. For a cloud provider, enter the required API key.
  3. Prefer a protected key file over a literal key in configuration: put the key in a user-only file, set mode 0600 on Linux/macOS, and enter file:/absolute/path/to/key in the API-key field.
  4. Save, then verify the selected provider and model in the panel before sending document information.
Protect credentials. Never commit keys, paste them into prompts, store them in AGENTS.md, or copy them into logs or screenshots. Windows ACL behavior is not yet fully verified; inspect file permissions manually.

4. Make a first reviewed change

  1. Open a new, disposable FreeCAD document.
  2. Start in Plan mode and prompt: Create a box 50 mm × 30 mm × 20 mm, but show me the plan before changing the document.
  3. Review the response. In Plan mode, generated Python is shown for review; Check is a compatibility preflight and does not prove that code is safe.
  4. Use Act mode when you want the assistant to apply bounded structured tools. Inspect the document after every operation and use FreeCAD undo if needed.
AI Python is powerful, not sandboxed. Raw Python is locked by default. Enable Allow AI Python only for the current FreeCAD process after reading the warning, then approve each individual code call. Approved code runs with your operating-system user privileges. Cancel if the code touches unexpected files, networking, shell commands, or documents. The control is not persisted; disarm it manually when finished.

Project instructions (AGENTS.md)

If an AGENTS.md or FREECAD_AI.md is found beside the document, in an allowed parent, or in the FreeCAD AI configuration directory, the app shows its source, root, manifest, fingerprint, and exact content before sending it to the provider.

  • Trust and send approves only the displayed fingerprint.
  • Ignore this version sends no project instructions.
  • Cancel cancels the request.
  • Changed content or a changed configuration-file fingerprint requires another preview.

5. Optional authenticated HTTP MCP

HTTP MCP requires a Bearer token on every request. The managed token is stored in <FreeCADAI dir>/mcp_server.token; startup reports the path, never the value. Start or stop the server only through an explicitly approved FreeCAD session.

This example reads the token from its file and passes the header through curl's standard input, so the token is not exposed in the process argument list:

export FREECAD_AI_MCP_URL='http://127.0.0.1:3000/mcp'
export FREECAD_AI_MCP_TOKEN_FILE='/private/path/mcp_server.token'

{ printf 'header = "Authorization: Bearer '; \
  tr -d '\r\n' < "$FREECAD_AI_MCP_TOKEN_FILE"; \
  printf '"\n'; } | \
curl --config - --silent --show-error \
  -X POST "$FREECAD_AI_MCP_URL" \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}'
Network limits: HTTP exposes run_macro but never execute_code. Use loopback by default. Private-LAN HTTP is unencrypted and allows same-LAN token capture; Internet, public, wildcard, multicast, and unspecified-address exposure is unsupported. Do not echo the token or enable shell tracing.

6. Troubleshooting checklist

  • Workbench missing: confirm the link/copy points directly to the repository and use the version-scoped v1.x/Mod directory for your FreeCAD release.
  • Provider error: confirm provider, model, endpoint, key reference, and key-file permissions; never work around TLS verification.
  • No response or tools: try a new chat, confirm Plan/Act selection, and check FreeCAD's Report view without sharing secrets.
  • AI Python unavailable: it is intentionally locked by default; enable it only when reviewed raw code is genuinely required.
  • AGENTS prompt appears: verify source, canonical root, fingerprint, and content. Cancel on anything unexpected.
  • HTTP MCP returns 401: confirm the token file and that the client sends one Bearer header on every request. Do not put the token directly on the command line.
  • HTTP bind rejected: use loopback or one explicitly approved private/link-local address; do not weaken the bind checks.
  • Potential leak or unsafe action: stop issuing requests, preserve evidence without secrets, and obtain approval before stopping or restarting any process.
